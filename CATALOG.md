# The curated catalog

`/catalog/` lists what Gravitas offers beyond its lessons: data, courses and
instruments, each reviewed before it was listed. A reader can install a data
pack or a course from it, for offline use, on the device they are using.

It is not an app store. Nothing in it runs code a maintainer has not reviewed
and compiled into Gravitas, and nothing is fetched from anywhere but this site.

## What is in it

`catalog/catalog.json` (`gravitas.catalog/1`) is generated by
`npm run catalog` at release time, and checked on every change by
`npm run catalog:check`, which CI runs. Two kinds of entry:

| | Built in | Archive |
|---|---|---|
| What | a capability package in `capabilities/`, compiled into Gravitas | a declarative extension from `extensions/`, accepted into `catalog/curation.json` |
| Delivered | with Gravitas; nothing to install | as a `.gxp` archive in `catalog/packages/`, from this origin |
| Kinds | lessons, instruments, data packs | data packs and courses only: never code |
| Size shown | what its assets cost when used | the download, and what it takes once installed |

Every entry carries its id, version and platform range, a title in each
language, what it provides, its licenses and citations, and its offline
class. An archive entry adds its checksum, its size, the files it holds with
their checksums, and its review: when it was accepted and which checks it
passed. The index also carries the lesson ids a course may name, with their
titles, so the page can check and show a course without loading the lesson
manifest.

Today it lists six: the four built-in packages, and two extensions built
outside the core with the SDK alone.

- **`community.su-dra-tess-s15`:** SU Draconis, an RR Lyrae star, from its
  TESS sector 15 light curve.
- **`community.pulsating-stars`:** a three-lesson course that ends on that
  light curve.

## What installing does, and refuses

`js/catalog/install.js` fetches the archive, and `js/catalog/archive.js` reads
it. Nothing in the archive is trusted until it has passed every check below,
in this order:

1. The entry's platform range accepts this Gravitas.
2. The archive is under 4 MB, and its SHA-256 is the catalog's, before a byte
   of it is decompressed.
3. It decompresses to under 16 MB, counted as it streams, so a gzip bomb
   stops at the limit.
4. The archive itself is sound:
   - every header's own checksum and the ustar magic hold;
   - every entry is a regular file, not a link or a directory;
   - every path is relative, with no `..`, no absolute path and no prefix
     field;
   - no entry appears twice, and there are at most 64;
   - the manifest comes first and `CHECKSUMS` last;
   - every entry matches its checksum, and every listed entry is there.
5. The manifest inside is a valid declarative package, and is the id and
   version the catalog names.
6. The content passes the platform's own checks:
   - a data pack's series decodes and is clean;
   - a course is a valid `gravitas.course-pack/1` whose lessons all exist.

Only then is it stored, in IndexedDB, in one transaction. A failure at any
step leaves what was installed before untouched. Each refusal has a stable
code, and the page says it in the reader's language, beside the entry, with a
retry where a retry could help.

A browser that will not keep IndexedDB gets a store that lasts until the page
closes, and the page says so rather than pretending.

**Offline.** The service worker precaches the page and its index, so a reader
offline can still see what they installed and remove it. The archives are
not precached. An installed pack is kept in IndexedDB, which is what makes it
work offline, and one not installed is not wanted offline.

**Using what was installed.**

- A data pack opens in the observatory, at
  `/observatory/?installed=<package id>`. The module that reads it loads only
  then, so a visitor who installs nothing pays nothing for it. The observatory
  now starts 5 KB lighter in the published sources, and 1.2 KB in the build.
- A course opens on the catalog page, as its units and notes, with a link into
  each lesson.

## Updates, migrations and old assignments

- **Status.** An entry is available, installed, an update (the catalog has a
  newer version, or the same version with another checksum), newer (a
  downgraded catalog), incompatible, or built in.
- **Updating** is installing again. The new version replaces the old in one
  write, or not at all.
- **A new major version** is flagged before the update: anything that names
  the old one may need to change.
- **Assignments pin their package.** A link made from a lesson a package
  provides now carries that package and its version (assignment schema 2,
  `js/assignments/assignment.js`). Opening one, `js/assignments/pinning.js`
  compares the pin with what the lesson comes from today:

  | The pin | What the student is told |
  |---|---|
  | the same package, the same major version | nothing: the step fingerprints already catch a rewritten question |
  | another major version | it was made with the old version, and rewritten steps are shown blank |
  | a package the lesson no longer comes from | it opens with the lesson as it is now |
  | no pin, on a lesson a package now provides | it predates versioned packages, and rewritten steps are shown blank |

  A schema 1 link still opens. Only one lesson, *What If Gravity Were Not
  Inverse Square?*, is provided by a package today, so only its links carry a
  pin.

## Rules for accepting an entry

A maintainer accepts an extension by adding it to `catalog/curation.json` in a
pull request. `npm run catalog:check`, which CI runs, refuses the pull request
unless every rule below holds, except the rebuild from the raw source. That
one needs the raw file, and `npm run packs:provenance` checks it, for these
packs and the built-in ones alike, where the file is cached.

1. **Declarative only.** A data pack or a course pack. An instrument, or
   anything else that runs code, is vendored into the core through the
   capability-package process (sdk/README.md, "Vendoring"). It is never served
   as an archive.
2. **Built with the public SDK.** The extension lives in its own directory
   under `extensions/`. Any build script imports `sdk/lib/api.mjs` and
   nothing else from Gravitas, and passes `npm run sdk -- validate` and
   `test`.
3. **Reproducible.**
   - A data pack pins its raw source by URL, size and SHA-256.
   - Rebuilding it from that source gives the committed files.
   - The archive holds exactly what `sdk pack` takes from the directory.
4. **Checked against the literature.** A data pack states a scientific check
   that `sdk test` runs (a transit's depth, a star's period), against a cited
   value, with a tolerance.
5. **Licensed for classrooms.** Every license is one of CC-BY-4.0, CC0-1.0,
   MIT, or public domain for NASA mission data (`ACCEPTED_LICENSES` in
   `tools/catalog.mjs`, with a reason for each). LICENSES.md covers the
   directory, and a data pack cites its sources.
6. **Compatible, and unique.** Its platform range accepts this Gravitas, and
   no public id collides with one the core or another entry uses.
7. **Reviewed, on the record.** The curation entry records the date and the
   checks it passed. The pull request that adds it records the review. Any
   scientific caveat belongs in the pack's own record: SU Draconis's says why
   RR Lyrae itself was not used.
8. **Versioned honestly.** A change to an accepted entry is a new version. A
   change that breaks what names it is a new major version, and says so in
   its migrations. The catalog's own `catalogVersion` rises with any change to
   its entries.

## What the SDK lacked

The SU Draconis pack and the course were built as an outside author would
build them: with only the published SDK and the documented extension points,
in directories outside the core. Every time that was not enough is recorded
here.

| What the extension needed | What was there | What changed |
|---|---|---|
| Reading its MAST product, a FITS file | `tools/data-packs/fits.mjs`, private | `readFits()` is public (SDK 1.2.0) |
| Binning it the way the built-in packs are binned | `binLightCurve()` in `tools/`, private | public as `binTessLightCurve()` |
| Encoding a star that swings from 0.77 to 1.46 of its median | `binned-relative-flux/1` holds ±3.3%, and the pipeline refused to clip | `binned-relative-flux/2`, flux in steps of `fluxStepPpm` |
| A scientific check for a pulsating star | only `folded-depth`, a transit's | `harmonic-period` |
| Validating a course in the browser | `sdk/lib/course.mjs`, SDK-only | moved to `js/platform/course.js`; the SDK re-exports it |
| A course naming the data pack it ends on | not in `gravitas.course-pack/1` | **not changed.** The note names it in words. A structured reference is a format change for the course-pack builder (Prompt 31) |
| A pack bringing its own kind of check | checks are SDK code | **not changed.** A new kind of variable needs a new check in the SDK |

The earlier gaps in sdk/README.md still stand: an instrument's strings and
drawing helpers are private, and registering an instrument is a core edit.
The catalog closes only the first: a curated declarative pack now reaches
readers without a core change.

**Why SU Draconis, not RR Lyrae.** The prototype was the first choice. The
TESS Input Catalog lists RR Lyrae (TIC 159717514) at Tmag 16.6 against its V
of 7.2, so SPOC treated it as a faint star:

- its aperture is 4 pixels, on a star that saturates across many more;
- it took 92% of the light for contamination (CROWDSAP 0.077);
- its PDCSAP flux goes negative.

SU Draconis (TIC 142848794) is catalogued at Tmag 9.45 against V 9.83. It
loses 1.5% of its light to neighbors, and has no Blazhko modulation. Its
sector 15 light curve gives a period of 0.660408 d from a 20-harmonic Fourier
series, against Monson et al.'s (2017) 0.66042001 d. The period moves by
10⁻⁶ d between 8 and 24 harmonics, while the reduced χ² falls from 388 to 32:
the check is robust, and the light curve's sharp rise needs many terms.

## Budgets

- **The application:** 818.4 of 830 KB at start-up, unchanged. Deferred, 4176.0
  of 4180 KB: 3.7 KB above v2, for the pinning notices in both deferred
  catalogs, the pinning modules and the stepped decoder. No ceiling was raised.
- **`/catalog/`:** 81.2 KB in 12 requests from the sources, and 36.2 KB in 1
  from the build, before anything is installed. The first ceilings are
  measured plus 0.5% and one request.
- **`/observatory/`:** 188.7 KB in 18 requests from the sources (was 193.7 in
  19), and 96.7 KB in the build (was 97.9). The pack decoder now arrives with
  the first observation opened. The ceilings were lowered to keep the saving.
- **The archives:** 12.4 KB for SU Draconis (24.0 KB installed) and 2.1 KB
  for the course (4.6 KB installed).

## Tests

- **`tests/catalog.test.js`:**
  - the browser reader reads every archive the catalog serves;
  - it refuses a traversal, an absolute path, a backslash and a prefix-field
    name;
  - it refuses a symlink, a hard link and a directory;
  - it refuses a duplicate, too many entries, and entries out of order;
  - it refuses a bad whole-archive checksum, a bad entry checksum, an
    unlisted entry and a missing entry;
  - it refuses a gzip bomb, an oversized archive, a damaged header, a
    truncated entry, and something that is not gzip at all;
  - install() refuses an incompatible entry, a built-in one, a failed
    download, a tampered archive, a version mismatch and a course with an
    unknown lesson, and leaves the store untouched each time;
  - statusOf() tells available, installed, update, newer and incompatible
    apart;
  - `binned-relative-flux/2` decodes exactly.
- **`tests/assignment.test.js`:** the pin, and all six pinning outcomes.
- **`e2e/catalog.spec.js`,** on the sources and `dist/`:
  - browsing, search and filtering;
  - installing, opening in the observatory, and removing;
  - an installed course and its lesson links;
  - a tampered archive, a failed download and the retries after them;
  - an incompatible entry, and a catalog that does not load;
  - no axe violations, in English and Spanish;
  - an installed pack opening offline (sources only).
- **`e2e/assignment.spec.js`:** a link that predates pinning, and one pinned
  to an older major version, each open with the notice that says so.
- **`npm run catalog:check`,** in CI.
