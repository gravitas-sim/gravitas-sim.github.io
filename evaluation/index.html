Classroom evidence kit

Everything an instructor needs to run one section on Gravitas, take a defensible pilot measurement, and hand a researcher a de-identified dataset — without an account, a server, or sending anything anywhere.

These are pilot instruments, developed for this project. The pre/post assessment below has not been through item analysis, reliability testing, or validation against an existing concept inventory, because none of that has been done. A score on it is a score on these twelve questions. It is not a measure of astronomy learning, and it should not be reported as one.

No study has been run on Gravitas. There is no measured learning gain. This page adds the paperwork somebody would need in order to change that; it changes nothing about what is currently known.

Before you collect anything

Using these to improve your own teaching is one thing. Collecting data from students with the intention of publishing it is another, and the line between them is drawn by your institution rather than by us.

  • Classroom improvement is not automatically research. Running a pre/post to decide whether to use Gravitas again next term is ordinary teaching practice. Running the same pre/post intending to write it up generally is research.
  • Institutional review is your responsibility. Research on students — including classroom research by their own instructor — usually needs approval before any data is collected, and consent that is genuinely optional when the person asking also assigns the grade. Retrospective approval is usually not available.
  • Gravitas transmits nothing. This page has no analytics, no telemetry and no submission endpoint. What you type stays in your own browser until you export it, and the export lands in your downloads folder. Nobody here receives your students' work or knows you ran this.

The sequence these items are written against

Three introductory investigations, thirty-five to forty-five minutes each, which is two or three class meetings: Kepler’s Laws, then Bound, Unbound and Escape, then Weighing the Stars. The assessment items are tied to the objectives those three state on their own cards. Run a different sequence and the items stop matching what was taught, which is the commonest way an instrument like this ends up measuring nothing.

1. Implementation and fidelity checklist

Filled in by the instructor, once, after the sessions. Without it a reader cannot tell a result from a deviation: a class where you worked three answers on the board is a different intervention from one where you did not.

  1. Which investigations were used, in order

    Ids or titles. If you ran only part of one, say which steps.

  2. Instructional setting

    ☐ lecture ☐ lab ☐ recitation ☐ homework ☐ mixed ☐ other

  3. Approximate contact time on Gravitas, in minutes

    Total across all sessions. An estimate is fine; leave blank if unsure.

  4. How students worked

    ☐ alone ☐ pairs ☐ small groups ☐ mixed

  5. Did you demonstrate or work through answers?

    This changes what the scores mean. It is not a failing to say yes.

    ☐ no ☐ demonstrated the interface only ☐ worked some answers ☐ worked most answers

  6. Major deviations from the intended procedure

    Skipped steps, technical failures, a fire drill, anything that would change how a reader reads the result.

2. Anonymous participant codes

Only needed if you want to compare each student’s own before and after. Skip it and you still get per-item before and after across the class.

How it works. Each student gets a code, writes it on a slip of paper they keep, and writes the same code on both sheets. You never hold a list linking codes to names, so there is nothing to lose.

What it costs, said plainly:

  • A student who loses the slip cannot be paired. Count them as unpaired rather than guessing — the summary tool does this for you.
  • Two students can pick the same code. The tool reports a collision instead of silently merging them.
  • Do not build codes from personal facts — initials, birth dates, mother’s maiden name. Those recipes are common and they are quasi-identifiers: in a class of twenty they can often be run backwards to a person, which is exactly what the code was for avoiding.

3. Pilot pre/post concept assessment

Twelve multiple-choice items, about ten minutes. Administer the same twelve before the sequence and after it. Three items each on orbital reasoning, measurement and inference, reading the model, and telling an illustration from a measurement.

The answer key is in js/data/evaluation.js and in the exported JSON template. It is deliberately not printed here, so this page can be handed to a class.

  1. A planet moves on a noticeably elliptical orbit around a star. Where is the star?

    1. At the centre of the ellipse
    2. At one focus of the ellipse, off centre
    3. At the point where the planet moves fastest
    4. At a point that shifts as the planet moves

  2. The same planet moves fastest when it is closest to the star. The best reason is that

    1. gravity is stronger there, so it is pushed along faster
    2. it is falling downhill and gravity has had longer to act
    3. the product of its distance and its sideways speed stays the same
    4. the star heats it and the extra energy speeds it up

  3. A probe is launched fast enough to escape a planet and never return. After it escapes,

    1. the planet no longer pulls on it
    2. the planet still pulls on it, but never enough to bring it back
    3. the pull reverses and pushes it away
    4. the pull stops once the probe passes the escape distance

  4. You measure the period and the semi-major axis of four planets around one star and plot log P against log a. A straight line of slope 1.5 tells you

    1. the orbits are circles
    2. the planets all have the same mass
    3. the period squared is proportional to the axis cubed
    4. the star is at the centre of each orbit

  5. To find the total mass of a binary pair from a simulation, the two quantities you most need to measure are

    1. the brightness of each star and their colours
    2. the size of the orbit and the time to go round once
    3. the temperature of each star and their separation
    4. the speed of the brighter star and its radius

  6. In a binary, the heavier star sits closer to the barycenter. If one star is three times further from the barycenter than the other, then

    1. the nearer star is three times heavier
    2. the further star is three times heavier
    3. the two stars have equal mass
    4. nothing can be said without knowing the period

  7. In Gravitas the bodies are drawn much larger than they would be to scale. The main consequence for a measurement is that

    1. distances between bodies are also wrong
    2. the drawn size cannot be used to judge how big anything is
    3. the masses are wrong by the same factor
    4. orbital periods come out too short

  8. The Gravitas engine is two-dimensional. Which conclusion does that make unsafe?

    1. that a single planet orbits its star on an ellipse
    2. that a heavier star produces a shorter orbital period at fixed distance
    3. that two planets whose orbits appear to cross would actually collide
    4. that a body below zero total energy is bound

  9. A body has kinetic energy 5 units and gravitational potential energy -8 units. It is

    1. unbound, because the kinetic energy is positive
    2. bound, because the total is negative
    3. exactly at escape
    4. impossible to classify without its mass

  10. Some things on the Gravitas screen are computed from the physics and some are drawn to illustrate. Which of these is computed?

    1. the glow around a star
    2. the jet drawn from a black hole
    3. the position of an orbiting body at each step
    4. the ripple animation after a merger

  11. The three-dimensional "spacetime" sheet dips beneath a massive body. A student says the depth of the dip is the curvature of spacetime near that body. The best response is

    1. correct, that is what the view shows
    2. correct, though only for black holes
    3. it is a drawing of the Newtonian gravitational potential, not a curvature
    4. it is meaningless and should be ignored

  12. Which of these numbers would you trust to two significant figures from Gravitas?

    1. the depth of the spacetime sheet under a star
    2. the width of a drawn accretion disk
    3. the orbital period measured with the on-screen timer
    4. the apparent size of a planet on screen

Project-developed, like the rest. If you want a System Usability Scale score, administer the actual System Usability Scale — it is ten specific items with a specific scoring procedure, and a score quoted from anything else is not a SUS score.

  2. student I could find the control or reading each step referred to.

5. Exports and analysis

The tools below need JavaScript. Everything above does not: print this page and the three instruments come out as paper forms.

Fill in and export

Nothing is sent anywhere. Responses are held in this browser until you export or clear them.

Once you have the files, the repository has a reader for them:

npm run evaluation:summary -- pre.csv post.csv

It prints sample counts, how much is missing, the per-item before and after, and the paired change where codes allow pairing. It prints no p-value and no verdict, because a convenience sample from one section measured with an unvalidated instrument supports a description and nothing else.

6. What the files look like

Schema version 1. CSV columns, in order:

schema, instrument, occasion, participant, q01 … q12

There is no column for a name, an email address, a student number or an institution, and there will not be one: a column that exists gets filled in, and a spreadsheet with a name in it is a spreadsheet that cannot be handed to anybody. Answers are stored as the zero-based index of the chosen option, or blank.

Part of Teaching with Gravitas and the instructor resources. The model page states what the simulation does and does not represent, which is worth reading before designing an item of your own.
